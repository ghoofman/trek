Trek vs Conductor

Both run coding agents in parallel, each in its own git worktree, on your Mac. Conductor wraps every workspace in a polished path from issue to merged pull request. Trek runs the agent CLIs you already use across every branch and repository, and keeps them going on a server of your own.

Checked against Conductor's docs, changelog and announcement in November 2026. Spot something out of date? Open an issue.

Conductor is winding down

On November 4, 2026, Conductor announced it is joining Meta. From that day new users can no longer sign up or download the app. Conductor Cloud goes read-only on November 13 and shuts down on November 20, and the local app keeps getting new models and critical bug fixes until early 2027.

  • Nov 4No new sign-ups or downloads
  • Nov 13Cloud workspaces go read-only
  • Nov 20Conductor Cloud shuts down
  • Early 2027Local app updates end

Choose Trek if you want

  • A tool you can download today, with a road ahead of it
  • The claude, codex, gemini and grok CLIs you've installed, plus local models
  • Agents that keep working on your own server after you close the laptop
  • One agent leading the others from a built-in panel
  • Projects that span several repositories, with workflow tags on every branch

Conductor may still suit you if

  • You already have it installed and lean on its pull request flow: diffs, create PR, CI checks and merge
  • You use setup, run and archive scripts with ports for every workspace
  • You start workspaces straight from Linear or GitHub issues
  • You run Cursor or OpenCode agents
  • You want to drive your Mac from the iPhone app today

Moving from Conductor

Most of what you know carries over. Here's where it lives in Trek.

Workspace→A worktree, or trail, created next to your repository as <repo>-<branch>
Parallel agents in a workspace→Session tabs on the worktree, each a real agent CLI
Workspace from a pull request→The + on a repository checks a PR out as a worktree
Linear issue→A ticket chip on the branch, with the issue's status and title
.context notes→Branch notes, kept even after the worktree is gone, and gathered in All Notes
Run actions→A dev stack per worktree, on your Mac
Conductor Cloud→trek-server on a machine you own, so agents keep going after you close the lid
iPhone remote control→Trek for iOS and Android, coming soon

Real CLIs

The guides you already trust.

Trek starts the claude, codex, gemini and grok you've installed, in a real terminal, so your config, skills, plugins and hooks come along. Local models work too, through Ollama or LM Studio.

Camp

A camp that doesn't close.

Conductor's way to keep agents running after you close the laptop was its cloud, which shuts down on November 20. Trek's camp is trek-server, running on a Mac, Windows or Linux machine you own, with no account and no analytics.

Expeditions

One guide leading the rest.

Trek's Global panel is an agent with tools to create worktrees, start sessions, queue prompts, read their terminals and wait for them, on your own machines. It can spread one plan across several repositories in the same project.

Trail log

Know where every branch stands.

Every branch carries a workflow tag, from In Progress to Ready to Deploy, along with its Linear issue, pull request and notes. Filter the sidebar by tag to see what's waiting on review and what's ready to ship.

Where Conductor is ahead today

Conductor built a lovely app, and some of its ground Trek hasn't covered yet. Its pull request flow takes a workspace from a Linear or GitHub issue through a diff viewer, PR creation with drafted descriptions, CI checks and review comments to merge. Its setup, run and archive scripts give every workspace its own ports, and its iPhone app can drive your Mac. If you already have it installed, it will keep working into early 2027.
